# 开发规范 —— AI 配置统一入口规范

> 生效日期：2026-09-18。适用于 EDOP 全部业务模块及 AI 公共模块。

## 1. 唯一入口（强制）

- 全局 AI 基础配置必须统一由【AI中心 → AI配置】维护，对应前端页面 `ruoyi-ui/src/views/ai/config/index.vue`。
- 业务模块不得再新增独立的“大模型配置”“AI配置”菜单，不得重复维护 API 地址、API Key、模型名称、Embedding 或月度限额。
- 历史业务模块配置页如需兼容，应设置 `sys_menu.visible='1'` 隐藏菜单入口，并在备注中明确“历史兼容入口”；待功能级开关完成迁移后再删除接口与页面。

## 2. 配置职责边界（强制）

- `ai.*`：平台级配置，由 AI 中心统一读写，包括全局开关、模型地址、密钥、模型名称、Embedding 与月度限额。
- `{module}.ai.*`：仅允许保存业务模块的功能级开关或专属策略，例如 `dms.ai.dispatch_recommend`；不得复制保存全局模型凭据。
- 业务功能调用统一依赖 `ruoyi-ai` 提供的客户端和配置解析能力，不得在业务模块重复实现密钥管理。

## 3. 用户提示与导航（强制）

- 涉及模型地址、密钥、模型名称、Embedding、限额或全局开关的提示，统一指向【AI中心 → AI配置】。
- 禁止使用“请在本模块 AI配置中处理”“AI助手-AI配置”等已失效导航文案。
- 模块专属能力未开启时，提示应区分“全局配置未完成”和“模块能力未开启”，不得误导用户重复录入模型配置。

## 4. 安全要求（强制）

- API Key 保存后不得通过任何业务模块接口回显；接口仅允许返回是否已配置标志。
- 输入留空表示沿用原密钥，禁止用空值或掩码覆盖已保存密钥。
- 数据库存储继续遵循 `ENC:` 前缀密文规范，业务模块不得绕过统一加解密链路。

## 5. 当前兼容项

- DMS 旧菜单组件 `dms/ai/config` 已隐藏，仅保留前后端兼容代码。
- DMS 维修知识库作为设备业务知识资产，位于【设备管理 → 维修知识库】，为设备管理直属菜单并排在数据采集之前；不得再挂在历史“AI助手”目录下。
- DMS 功能级开关 `dms.ai.repair_assistant`、`dms.ai.dispatch_recommend`、`dms.ai.knowledge_qa` 暂时保留，后续迁移至 AI 中心“模块能力配置”后再清理旧接口。
