## 一、现状分析结论（结论先行）

### 1.1 现有代码结构

安全生产模块（`ruoyi-safety`）当前包含 21 个业务实体，按业务域划分：

| 业务域 | 实体（Domain / Controller / Service / Mapper 齐备） |
|---|---|
| 基础数据 | 区域 SafetyArea、企业 SafetyEnterprise、设备 SafetyEquipment、员工 SafetyWorker、物料 SafetyMaterial |
| 风险管控 | 风险点 SafetyRiskPoint、隐患 SafetyHazard（含审计日志）、检查任务 SafetyInspectionTask、整改 SafetyRectify |
| 应急管理 | 应急预案 SafetyEmergencyPlan、应急物资 SafetyEmergencyMaterial、演练 SafetyDrill |
| 证书与事件 | 证书 SafetyCert、事件 SafetyIncident、提醒 SafetyRemind |
| **培训管理** | 培训计划 SafetyTrainingPlan、课程 SafetyTrainingCourse、培训记录 SafetyTrainingRecord、参训人 SafetyTrainingAttendee、培训证书 SafetyTrainingCert、学时统计（hours） |
| 辅助 | AI 助手 SafetyAiAssist、驾驶舱 SafetyDashboard |

### 1.2 考试功能现状核查

对后端 Java/XML 与前端 `views/safety`、`api/safety` 全量检索 `exam|考试|题库|试卷|question|quiz` 后，结论如下：

| 能力 | 现状 | 证据 |
|---|---|---|
| 题库管理 | ❌ **无**。无任何题目表/实体，题目仅存在于 AI 接口返回的临时 JSON 中 | 全模块无 Question 实体 |
| 试卷生成 | ❌ **无**。无试卷表、无组卷逻辑 | 无 Paper 相关类 |
| 在线考试 | ❌ **无**。前端 `views/safety/training/` 仅有 attendee/cert/course/hours/plan/record 六个页面，无答题页 | 目录核查 |
| 自动判分 | ❌ **无**。成绩为人工批量录入：`SafetyTrainingAttendeeController#batchExamScore` 直接更新 `exam_score/is_pass/exam_time` 三字段 | Mapper XML `batchUpdateExamScore` |
| 成绩统计 | ⚠️ **仅最简**。考试分数挂在参训人表上，随学时统计导出，无独立成绩分析 | `SafetyTrainingHoursExportVO` |
| AI 出题 | ⚠️ **半成品**。`SafetyAiAssistController#trainingQuiz` 可根据培训记录生成 7 道题（5 单选 + 2 判断）的 JSON，但**不入库、不答题、不判分**，仅前端展示 | 权限 `safety:ai:trainingQuiz` |

### 1.3 结论

> **当前安全生产模块不具备考试功能闭环。** 现有实现仅覆盖"考试结果登记"（人工录分）与"AI 即时出题预览"两个孤立点，缺少题库、组卷、在线答题、自动判分、成绩分析五个核心环节。本方案补齐该闭环，并与现有培训模块打通。

## 二、问题陈述（Why）

- **一线员工**：安全培训后考核依赖线下纸质试卷或主管人工录分，考试组织成本高、无过程留痕；一次培训 50 人需人工录 50 条成绩。
- **安全管理人员**：无法沉淀自有题库，每次出题从零开始；无法按课程/工种/难度复用题目；成绩数据散落在参训表，无法回答"哪些工种合格率偏低""哪些题目错误率最高"。
- **企业合规**：安全生产法要求"先培训、后上岗"，考核记录是检查重点；当前只有分数结果、无试卷与答题明细，审计追溯能力弱。
- **不做的代价**：培训闭环断在考核环节，AI 出题能力被浪费（生成即丢弃），模块在投标/演示场景中缺少"在线考试"这一高感知亮点功能。

## 三、目标（Goals）

1. **效率**：培训考核从"人工录分"变为"自动判分"，单场 50 人考试的录分工作量降为 **0**（客观题全自动）。
2. **闭环**：培训记录 → 关联考试 → 自动判分 → 回写参训人成绩/合格状态 → 自动生成培训证书，全链路无人工干预点。
3. **沉淀**：上线 3 个月内题库积累 ≥200 题，题目复用率（被 2 张以上试卷引用的题目占比）≥30%。
4. **合规**：每场考试可导出含答题明细的存档（谁、何时、答了什么、得分），满足安全检查追溯要求。
5. **洞察**：提供按课程/部门/工种的合格率统计与错题率 Top 榜，指导下一轮培训重点。

## 四、非目标（Non-Goals）

| 非目标 | 原因 |
|---|---|
| 主观题（简答/论述）AI 判分 | 判分准确性与合规风险高，v1 仅支持客观题，主观题留人工补录通道 |
| 视频监控/人脸识别防作弊 | 硬件依赖重、成本高，v1 仅做切屏检测与题目乱序等轻量手段 |
| 题库市场/题目共享交换 | 当前为单企业内部使用，无共享场景 |
| 移动端 App/小程序答题 | v1 覆盖 PC 端（响应式兼容平板）；移动端列为 P2 |
| 独立学习中心/课程视频播放 | 与培训课程播放属另一条产品线，不混入考试模块 |

## 六、功能需求

### 6.1 P0 — Must Have（v1 交付范围）

#### FR-1 题库管理
- 题目字段：题干、题型（单选/多选/判断）、选项（判断题固定"正确/错误"）、正确答案、答案解析、题目分类（关联课程类别/自定义分类）、难度（简单/中等/困难）、关联工种（可多选）、状态（启用/停用）。
- 支持：单题新增/编辑/删除（删除为逻辑删除）、批量导入（Excel 模板下载 + 导入校验报告）、按分类/题型/难度/关键词筛选、启用停用。
- 校验规则：单选/判断答案唯一；多选答案 ≥2 项；选项 ≥2 个且不为空；同分类下题干查重提示（不强制）。

#### FR-2 试卷生成
- 两种组卷方式：
  - **手动组卷**：从题库逐题勾选，实时显示题型/难度/总分统计。
  - **随机组卷**：按规则（各题型数量 × 难度分布 × 指定分类/工种）从题库随机抽取，不满意可一键重抽单题。
- 试卷字段：名称、关联课程（可选）、总分（按题型分值配置自动计算）、及格分、时长（分钟）、题目乱序开关、选项乱序开关、切屏限制次数（0=不限）。
- 规则：试卷发布后题目集合**冻结**（快照式存储，原题后续修改不影响已发布试卷）；同一试卷题目不可重复。

#### FR-3 考试管理（场次）
- 基于试卷发起考试场次：指定考试时间窗口（开始/结束时间）、时长、参考人员（按部门/工种/从培训记录参训人勾选）。
- 状态机：`草稿 → 已发布 → 考试中 → 已结束`；已发布未开始的场次可撤回（撤回后考生端不可见）；已开始的场次不可撤回仅可强制结束。
- 每个考生生成一条考试记录，未作答的考生在考试窗口结束后标记为"缺考"。

#### FR-4 在线考试（答题端）
- 考生进入考试前展示须知（时长/题型分布/及格分/切屏规则），确认后开始计时。
- 答题页：题型分块展示、答题卡导航（已答/未答标识）、剩余时间倒计时、单题保存草稿（防断页丢失）。
- 提交：手动提交；时间耗尽自动提交；**同一考试同一考生仅允许一次有效提交**（后端幂等校验）。
- 交卷后即时出分（客观题），显示总分/是否合格/逐题对错与解析（可配置是否展示解析）。

#### FR-5 自动判分
- 判分规则：单选/判断答案完全一致得满分，否则 0 分；多选**全对得满分；漏选得该题分值 × 50%（计分精度 0.5 分，如 4 分题漏选得 2 分）；错选得 0 分**。该规则在管理员端做成可配置项（默认 50%），呼应开放问题 Q1。
- 判分在后端提交时进行并以 `judge_status` 记录（auto：已自动判分），防篡改。
- 判分完成后自动回写培训链路：若考试关联了培训记录，则将分数、是否合格、考试时间回写 `safety_training_attendee` 的 `exam_score/is_pass/exam_time` 字段（复用现有 `batchUpdateExamScore` 语义，改为服务层调用）。

#### FR-6 成绩统计与导出
- 场次维度：参考人数、实考/缺考、平均分、最高/最低分、合格率、分数段分布（<60/60-70/70-80/80-90/90-100）。
- 题目维度：每题正确率，错误率 Top10 榜。
- 人员维度：个人成绩明细（答题快照、对错、得分）。
- 成绩单导出 Excel（复用 RuoYi `@Excel` 注解导出模式），含答题明细的存档导出（P0 简版：逐题对错；完整答题原文导出列 P1）。

## 七、数据结构设计

命名延续安全模块前缀 `safety_`，全部含 RuoYi 标准审计字段（`create_by/create_time/update_by/update_time/remark`）与 `del_flag`。

```sql
-- 1. 题库表
CREATE TABLE safety_exam_question (
  question_id     BIGINT       PRIMARY KEY AUTO_INCREMENT COMMENT '题目ID',
  question_type   CHAR(1)      NOT NULL COMMENT '题型（1单选 2多选 3判断，字典 safety_exam_question_type）',
  content         TEXT         NOT NULL COMMENT '题干',
  options         JSON         NOT NULL COMMENT '选项数组 ["A内容","B内容",...]；判断题固定["正确","错误"]',
  answer          VARCHAR(20)  NOT NULL COMMENT '正确答案，如 A / ABD / 对',
  analysis        VARCHAR(500) COMMENT '答案解析',
  category_id     BIGINT       COMMENT '题目分类ID（safety_exam_category）',
  difficulty      CHAR(1)      DEFAULT '2' COMMENT '难度（1简单 2中等 3困难）',
  job_types       VARCHAR(200) COMMENT '适用工种，逗号分隔',
  status          CHAR(1)      DEFAULT '0' COMMENT '状态（0启用 1停用）',
  del_flag        CHAR(1)      DEFAULT '0',
  -- 标准审计字段略
  KEY idx_category (category_id), KEY idx_type_diff (question_type, difficulty)
) COMMENT='安全生产考试题库';

-- 1.1 题目分类表
CREATE TABLE safety_exam_category (
  category_id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '分类ID',
  category_name VARCHAR(50) NOT NULL COMMENT '分类名称（如：消防/电气/高处作业）',
  parent_id   BIGINT DEFAULT 0 COMMENT '父分类ID（支持两级）',
  order_num   INT DEFAULT 0,
  status      CHAR(1) DEFAULT '0', del_flag CHAR(1) DEFAULT '0'
) COMMENT='题库分类';

-- 2. 试卷表
CREATE TABLE safety_exam_paper (
  paper_id      BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '试卷ID',
  paper_name    VARCHAR(100) NOT NULL COMMENT '试卷名称',
  course_id     BIGINT COMMENT '关联培训课程（safety_training_course）',
  total_score   DECIMAL(5,1) NOT NULL COMMENT '总分',
  pass_score    DECIMAL(5,1) NOT NULL COMMENT '及格分',
  duration      INT NOT NULL COMMENT '考试时长（分钟）',
  shuffle_question CHAR(1) DEFAULT 'N' COMMENT '题目乱序（Y/N）',
  shuffle_option   CHAR(1) DEFAULT 'N' COMMENT '选项乱序（Y/N）',
  switch_limit  INT DEFAULT 0 COMMENT '切屏限制次数（0不限）',
  show_analysis CHAR(1) DEFAULT 'Y' COMMENT '交卷后展示解析（Y/N）',
  status        CHAR(1) DEFAULT '0' COMMENT '状态（0草稿 1已发布 2停用）',
  del_flag      CHAR(1) DEFAULT '0'
) COMMENT='考试试卷';

-- 2.1 试卷-题目关联表（发布时快照题目内容，防源题修改影响）
CREATE TABLE safety_exam_paper_question (
  id           BIGINT PRIMARY KEY AUTO_INCREMENT,
  paper_id     BIGINT NOT NULL,
  question_id  BIGINT NOT NULL COMMENT '来源题目ID',
  question_type CHAR(1) NOT NULL,
  content      TEXT NOT NULL COMMENT '题干快照',
  options      JSON NOT NULL COMMENT '选项快照',
  answer       VARCHAR(20) NOT NULL COMMENT '答案快照（判分依据）',
  analysis     VARCHAR(500),
  score        DECIMAL(4,1) NOT NULL COMMENT '本题分值',
  sort_no      INT DEFAULT 0,
  KEY idx_paper (paper_id)
) COMMENT='试卷题目明细（快照）';

-- 3. 考试场次表
CREATE TABLE safety_exam (
  exam_id      BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '考试ID',
  exam_name    VARCHAR(100) NOT NULL COMMENT '考试名称',
  paper_id     BIGINT NOT NULL,
  record_id    BIGINT COMMENT '关联培训记录（safety_training_record），可空',
  start_time   DATETIME NOT NULL COMMENT '考试开始时间',
  end_time     DATETIME NOT NULL COMMENT '考试结束时间（窗口）',
  exam_status  CHAR(1) DEFAULT '0' COMMENT '状态（0草稿 1已发布 2考试中 3已结束 4已撤回）',
  publish_by   VARCHAR(64), publish_time DATETIME,
  del_flag     CHAR(1) DEFAULT '0'
) COMMENT='考试场次';

-- 4. 考生记录表（一人一场一条）
CREATE TABLE safety_exam_record (
  record_id    BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '考试记录ID',
  exam_id      BIGINT NOT NULL,
  user_id      BIGINT NOT NULL COMMENT '考生用户ID（sys_user）',
  worker_id    BIGINT COMMENT '关联员工（safety_worker），可空',
  attendee_id  BIGINT COMMENT '关联培训参训人（safety_training_attendee），可空',
  paper_id     BIGINT NOT NULL,
  start_time   DATETIME COMMENT '本人开始答题时间',
  submit_time  DATETIME COMMENT '提交时间',
  used_seconds INT COMMENT '实际用时（秒）',
  submit_type  CHAR(1) COMMENT '提交方式（1手动 2超时自动 3切屏强制）',
  total_score  DECIMAL(5,1) COMMENT '总得分',
  is_pass      CHAR(1) COMMENT '是否合格（Y/N）',
  judge_status CHAR(1) DEFAULT '0' COMMENT '判分状态（0未交卷 1已自动判分）',
  switch_count INT DEFAULT 0 COMMENT '切屏次数',
  exam_result  CHAR(1) DEFAULT '0' COMMENT '考试状态（0未开始 1进行中 2已交卷 3缺考 4已判分）',
  UNIQUE KEY uk_exam_user (exam_id, user_id)
) COMMENT='考生考试记录';

-- 5. 答题明细表
CREATE TABLE safety_exam_answer (
  answer_id    BIGINT PRIMARY KEY AUTO_INCREMENT,
  record_id    BIGINT NOT NULL,
  paper_question_id BIGINT NOT NULL,
  user_answer  VARCHAR(20) COMMENT '考生答案（如 A / ABD；空=未答）',
  is_correct   CHAR(1) COMMENT '是否正确（Y/N）',
  score        DECIMAL(4,1) DEFAULT 0 COMMENT '本题得分',
  UNIQUE KEY uk_record_question (record_id, paper_question_id)
) COMMENT='答题明细';
```

**设计要点说明：**
1. **快照式组卷**：`safety_exam_paper_question` 冗余存储题干/选项/答案，题库题目修改、停用、删除均不影响已发布试卷的完整性与判分一致性。
2. **幂等约束**：`safety_exam_record` 对 `(exam_id, user_id)` 建唯一索引，后端再校验 `exam_result`，双重防止重复提交。
3. **与培训链路的外键挂点**：`safety_exam.record_id → safety_training_record.record_id`、`safety_exam_record.attendee_id → safety_training_attendee.attendee_id`，判分后回写，不改动现有培训表结构。
4. **菜单/字典**：新增字典 `safety_exam_question_type`、`safety_exam_difficulty`、`safety_exam_status`；菜单 SQL 随模块交付（`deploy/` 目录惯例）。

## 九、页面与交互流程

### 9.1 管理端主流程

```
题库管理 → 试卷生成 → 发起考试 → 监控/强制结束 → 成绩统计 → 导出存档
   │            │            │
   │  Excel导入 │ 随机组卷    │ 勾选参训人(或从培训记录带入)
   └────────────┴────────────┘
```

1. **题库页**：左侧分类树 + 右侧题目列表；新增/编辑为抽屉表单（题型切换联动选项编辑器）；"导入"按钮提供模板下载与结果回显（成功 n 条 / 失败 m 条及原因）。
2. **试卷页**：列表 + 组卷弹窗。组卷弹窗左半为题库筛选选题区（多选/判断/单选分 tab），右半为已选题目与分值配置；"随机组卷"输入各题型数量与难度分布后一键填充。试卷"发布"后状态锁定并弹出确认。
3. **考试场次页**：选试卷 → 设时间窗口 → 选人（部门树 + 勾选，或"从培训记录带入"）→ 发布。列表显示实时"已交卷/应考"进度条，提供"强制结束"与"成绩单"入口。
4. **统计页**：场次详情内三个 tab（成绩单 / 题目分析 / 分数段分布图），成绩单支持导出。

### 9.2 考生端答题流程

```
我的考试列表 → 阅读考试须知 → 开始考试(计时) → 逐题作答(草稿实时保存)
   → 答题卡检查漏答 → 提交 → 即时出分页(得分/合格/逐题对错/解析)
```

- 考试入口：首页"我的考试"卡片 + 菜单"我的考试"页，仅显示本人且处于时间窗口内的考试。
- 倒计时基于 `start_time + duration` 服务端计算，前端仅展示；**每次进入以服务端剩余时间为准**，防本地改时。
- 提交前答题卡红点提示未答题数，需二次确认。
- 出分页按试卷 `show_analysis` 配置决定是否展示逐题解析。

### 9.3 关键交互约束

- 答题页全屏路由、禁用浏览器右键、切屏监听（P1）；断网恢复后从服务端拉取草稿续答。
- 所有管理端列表操作遵循现有模块的权限按钮显隐（v-hasPermi）与逻辑删除确认弹窗惯例。

## 十、权限控制

延续 `@ss.hasPermi` + 前端 `v-hasPermi` 模式，权限串规划：

| 权限串 | 说明 | 默认角色 |
|---|---|---|
| `safety:exam:question:list / query / add / edit / remove / import` | 题库管理 | 安全管理员 |
| `safety:exam:paper:list / query / add / edit / remove / publish` | 试卷管理（publish 控制发布/撤回） | 安全管理员 |
| `safety:exam:list / query / add / edit / remove / publish / forceEnd / export` | 考试场次管理 | 安全管理员 |
| `safety:exam:stats` | 成绩统计查看 | 安全管理员 |
| `safety:exam:take` | 考生答题（进入须知/答题/提交/查分） | 全员（普通员工） |
| `safety:exam:myList` | 我的考试列表 | 全员（普通员工） |
| `safety:exam:score:edit` | 人工调分（含主观题补录，仅查分页对单条成绩启用） | 安全管理员（可审计，记录操作日志） |

**权限控制要点：**
1. **数据权限**：考生仅能访问 `safety_exam_record.user_id = 当前用户` 的记录；后端答题接口强制校验归属，防止越权代考（横向越权：校验 record 归属 + 考试状态机）。
2. **答案保密**：题库的 `answer/analysis` 字段**仅管理端接口返回**；考生答题接口返回的题目数据剥离答案字段，防 F12 抓包作弊。
3. **按钮级**：发布/强制结束/调分等敏感操作独立权限串并写 `sys_oper_log`。
4. **菜单**：普通员工仅分配"我的考试"菜单；管理员分配"考试管理"目录（题库/试卷/场次/统计）。

## 十一、异常场景处理

| # | 场景 | 处理策略 |
|---|---|---|
| E1 | 考试窗口结束瞬间仍在答题 | 前端倒计时到 0 自动提交；后端以提交时间戳 ≤ end_time+30s 宽限判定有效，超宽限按"超时未交"处理并按已保存草稿判分 |
| E2 | 断网/页面崩溃 | 每题作答实时保存草稿（answer 表即时 upsert，exam_result=进行中）；重新进入按服务端剩余时间续答 |
| E3 | 重复点击提交/并发双开页签提交 | `(exam_id,user_id)` 唯一索引 + `exam_result` 状态机双重校验，第二次提交返回"已提交"，以先到达的为准 |
| E4 | 时间耗尽未答任何题 | 超时自动提交空卷 → 判 0 分，`submit_type=2` |
| E5 | 缺考 | 窗口结束无任何开始记录 → `exam_result=3 缺考`，不计分，统计单列 |
| E6 | 题库题目在试卷发布后被停用/删除 | 快照机制保证试卷与判分不受影响；源题删除为逻辑删除 |
| E7 | 考试进行中管理员强制结束 | 状态置已结束并拒绝新提交；已开始考生按当前草稿即时判分 |
| E8 | Excel 导入格式错误 | 逐行校验（题型/答案合法性/选项数量），返回失败行号+原因清单，合法行不导入（全量回滚，避免半批数据） |
| E9 | 多选题部分正确 | 全对满分；漏选得该题分值 × 50%（精度 0.5 分）；错选 0 分；规则在须知页明示，且管理端可配置 |
| E10 | 服务器时钟偏差 | 判定一律以数据库时间 `NOW()` 为准，前后端时间差 >5s 时前端提示刷新 |
| E11 | 切屏作弊（P1） | 记录次数与时间点；超 `switch_limit` 自动交卷并 `submit_type=3` 标记，成绩单醒目标识供管理员裁定 |
| E12 | 考生未关联 sys_user（纯工人档案） | v1 仅支持有系统账号人员在线考试；无账号人员仍走原人工录分通道，不阻塞培训流程 |

### 12.2 实施步骤（按依赖排序）

1. **S1 数据层先行**：DDL 评审（重点确认快照与幂等设计）→ 执行 `deploy/` SQL 入库 → 生成域对象/Mapper（RuoYi 代码生成器 + 手工调整）。
2. **S2 题库**：后端 CRUD + 导入 → 前端题库页。**验收**：导入 100 题零错行、答案字段不出现在考生接口。
3. **S3 试卷**：组卷服务（含随机抽题 SQL 与防重复）→ 前端组卷弹窗 → 发布冻结快照。**验收**：发布后修改源题，已发试卷内容不变。
4. **S4 场次与答题**：场次状态机 + quartz 状态流转任务 → 考生端须知/答题/倒计时/草稿/提交。**验收**：双开页签并发提交仅一次生效；断网续答草稿不丢。
5. **S5 判分与统计**：判分策略 + 培训回写（事务内）→ 统计页 + 导出。**验收**：50 人模拟考试自动判分结果与人工抽核一致；参训人表成绩自动回写。
6. **S6 P1 增强**：按 FR-7~12 顺序迭代，错题分析（FR-7）最先做（依赖 S5 数据已积累）。
7. **贯穿**：每阶段交付配套权限 SQL 与操作日志；S5 完成后组织一次 UAT（管理员组卷一场真实培训考核 + 员工端答题）。

### 12.3 关键技术风险

| 风险 | 缓解 |
|---|---|
| 判分与回写的事务一致性 | 判分、成绩回写、attendee 更新放同一 `@Transactional`；失败可由 quartz 补偿任务重扫 `judge_status` |
| 草稿高频写库 | 前端 800ms 防抖批量 upsert；answer 表加 `(record_id, paper_question_id)` 唯一键 upsert |
| quartz 依赖 | 若部署环境未启用 quartz 模块，降级为"惰性状态流转"（查询时判断时间窗口即时纠正状态） |

- 开发/测试环境：复用现有 RuoYi 开发库，新增 7 张表 + 3 个字典 + 菜单 SQL 入 `deploy/` 目录（沿用模块惯例，含回滚 DROP 脚本）。

## 十九、发布与运营计划（v1.1 补充）

### 19.1 发布流程与回滚

1. **发布包**：后端 jar + 前端 dist + `deploy/` SQL（DDL、字典、菜单、权限，全部带 IF NOT EXISTS/幂等写法 + 对应回滚脚本）。
2. **上线顺序**：测试环境全量回归 → 生产库执行 SQL（备份先行）→ 后端发版 → 前端发版 → 冒烟（建 1 张测试试卷 + 管理员账号自答一场）。
3. **灰度策略**：首场真实考试选 1 个部门（≤20 人）试点，跑通后全企业推广。
4. **回滚方案**：代码回滚至上一版本（新表保留不删，无数据破坏性）；SQL 层仅需停用新增菜单（`visible='1'`）即可对用户隐形；数据层回滚脚本仅作灾难兜底，需阿磊二次确认后执行。

### 19.2 运营与推广

## 二十、市面主流考试系统对标分析（v1.1 补充）

选取市面常用的在线考试系统作为功能基线参照：**考试星**（云端严肃考试代表）、**优考试**（全场景机考/私有化代表），并参照开源 **学之思（xzs）** 等自建系统常见能力。对标目的：校准本方案的功能边界——不追求大而全，聚焦企业内训考核场景。

### 20.1 功能维度对标

| 能力维度 | 市面主流（考试星/优考试付费版基线） | 本方案 | 差距定性 |
|---|---|---|---|
| 题型覆盖 | 单选/多选/判断/填空/问答/组合题/音视频题/附件题 | 单选/多选/判断（客观题） | **有意收窄**：主观题判分风险与工作量高，留 P2 `short_answer` 预留位 |
| 录题方式 | 手动 + Excel/Word 批量 + AI 智能录题 + 题目查重 | 手动 + Excel 导入；AI 出题入库（P1） | 基本对齐；题目查重列为 P1 增强项 |
| 题库组织 | 无限级分类 + 标签 + 难度系数 | 两级分类 + 工种多选 + 三档难度 | 够用；企业内训题量（≤5000）无需无限级 |
| 组卷模式 | 固定卷/随机卷/抽题卷/混合卷，一人千卷 | 手动固定卷 + 随机抽题卷（含题目/选项乱序） | 对齐核心两种；"抽题卷"（每人按规则独立抽题）列为 P2 |
| 考务管理 | 定时考试、子账号分工（题库员/监考员/阅卷员） | 场次时间窗口 + 状态机 + 权限串 | 对齐核心；考务子账号分工依赖现有 RuoYi 角色体系，暂不单建岗位 |
| 防作弊 | 人脸核验、多路视频监考、霸屏客户端、禁复制粘贴、切屏强制交卷 | 切屏检测 + 题目/选项乱序（P1） | **明确差距，接受**：内训考核信任成本低，硬件监考 ROI 不成立（Non-goal 已声明）；禁复制粘贴、无操作超时检测成本极低，**纳入 P1**（新增 FR-13） |
| 判分阅卷 | 客观自动 + 主观人工/流水阅卷/AI 阅卷 | 客观自动 + 人工调分留痕 | 客观题范围下完全对齐 |
| 成绩分析 | 及格率/分数段/试题正确率/部门对比/能力模型/答题时间分析 | 场次三维度统计 + 错题率 Top10 + 分数段（P1 复训推荐） | 对齐企业内训所需；"能力模型/答题时间分析"不引入 |
| 证书发放 | 培—考—证一体化，电子证书带唯一二维码 | P1 与 SafetyTrainingCert 联动 | 对齐（依托已有证书模块） |
| 并发能力 | 万人级统考、实时监考大屏 | 单场 ≤100 人 | 场景决定，无需对标 |
| 部署形态 | SaaS/混合云/私有化/信创 | 企业自建 RuoYi 内网部署（天然私有化） | **自建优势**：数据不出内网，无年费 |

### 20.2 对标结论（三点）

1. **功能边界成立**：本方案在"题库—组卷—在线答题—自动判分—成绩分析—培训闭环"主链路上与市面付费版基线一致；差距集中在防作弊硬件与主观题阅卷，均属内训场景低 ROI 项，维持 Non-goal 判断。
2. **自建 vs 采购**：若企业仅需考试工具，SaaS 年费约数千至数万元且数据在外部云；本方案依托现有 RuoYi 体系 21 人日交付、数据内网留存、且与培训/证书/员工模块天然打通——**集成价值是采购方案不具备的**，自建决策合理。
3. **吸收项（本轮已纳入）**：① 新增 **FR-13（P1）**：禁复制粘贴/禁右键 + 无操作超时自动锁卷（对标考试星，纯前端实现，成本 <1 人日）；② P1 增强题库**题目查重**（导入时题干相似度提示）；③ P2 预留"抽题卷"模式（一人一卷随机抽题，用于正式资格类考核升级）；④ 判分规则可配置化已在 FR-5 落实（对标市面"规则可配"惯例）。
