## 三、自洽性检查：发现的逻辑矛盾（2 处，均已修正）

### 缺陷 1：架构依赖自相矛盾（最严重）
v1.0 同时主张三个互相冲突的说法：
- ① "决策模块不直连任何业务 Mapper"；
- ② "bi 通过调用各模块 `IModuleStatsService` 接口取数"；
- ③ 平台既有规范 6.1/6.2 允许跨模块 SQL JOIN。

若 bi 在 Maven 层依赖 8 个业务模块以调用其接口，形成依赖网，与规范 6.1 分层依赖方向冲突，也使"模块裁剪"更难——恰恰违背了改造初衷。

**v1.1 修正**：`IModuleStatsProvider` 接口**定义在 `ruoyi-common`**，各模块基于其**现有 DashboardService/StatisticsService 扩展实现**（复用既有取数，不新建平行实现），bi 通过 Spring 注入 `List<IModuleStatsProvider>` 自动收集——bi 的 pom 不含任何业务模块依赖，且新增验收标准"bi 的 pom.xml 不含业务模块依赖"。

### 缺陷 2：数据权限表述与平台框架冲突
v1.0 自创"数据权限规则 = 各模块规则的并集取交集（从严原则）"——平台实际已有强制的 `@DataScope` 切面框架（规范 3.5，已全平台接入 22 处查询 + 47 张表），自创规则既无法实现也不必要。且 v1.0 未说明快照表如何过数据权限（快照脱掉了单据归属信息，无法回溯过滤）。

**v1.1 修正**：快照表按 3.5.1 分类为统计/追溯类（豁免归属填充），但**必须带 dept_id 维度列**，各模块写入时按归属部门分粒度落库；查询按 DataScope 等效语义过滤 dept 维度；删除"并集取交集"表述。
