## 二、缺陷清单（本轮发现并修复）

| # | 缺陷 | 性质 | 影响 | 状态 |
|---|---|---|---|---|
| D1 | `FinInventoryCostMapper.updateCost` 在全部 `<if>` 为空时生成 `sysdate(), WHERE` | **既有** | SQL 语法错误，台账更新失败 | ✅ 已修 |
| D2 | `doPutaway` 用「同物料同批次汇总已上架量」对比「本行已收数量」 | **既有** | 同物料多行时合法上架被误拒 | ✅ 已修 |
| D3 | 兜底价（不含税）被当作含税价再次除税 | **本次引入** | 成本系统性低估（实测少计 352.33 元） | ✅ 已修 |
| D4 | 盘亏截断到零时逐次舍入残留 `-0.01` | **本次引入** | 台账负金额、流水与结存差 0.01 | ✅ 已修 |

### D2 复现细节

物料 1 两行明细：`d107`（计划 10 / 单价 25.50）、`d108`（计划 4 / 单价 12.00）。

```
d107 收 10 → 上架 10   ✅
d108 收 4  → 上架 4   ❌ "上架数量不能超过已收数量"
```

原因：`totalPutaway` 汇总了 d107 的 10 + d108 的 0 = 10，
再与 `d108.receivedQty = 4` 比较，`4 < 10 + 4` → 误判超收。
修正为按行校验 `本行已上架 + 本次 ≤ 本行已收`。

### D4 复现细节

台账 `qty=100`、`total_cost=7079.65`、`unit_cost=70.7965`，盘亏 500（超过结存）。

```
期望：qty=0.00, total_cost=0.00, 流水金额=7079.65
实际：qty=0.00, total_cost=-0.01, 流水金额=13451.34  ❌
```

原因：`calcOutboundWeighted` 内部先 `qty×unit` 舍入再相减，两次舍入产生残差。
修正为全额冲减时直接取结存金额清零。

## 六、遗留问题（已知边界，非缺陷）

1. **物料 37 `TMAT155942` 无税率档案**
   → 盘盈调账持续 `fail`（三级取价走到除税时抛错）。
   **这是受控拒绝**：宁可失败也不写 0 成本。需补 `fin_material_tax`。

2. **物料 38 `RMAT162519` 已软删除但仍有 5 有效库存**
   → 取价查询带 `del_flag='0'`，该行金额显示 `-`。
   **刻意不取已删物料的价格**；建议清理该孤儿库存。

3. **盘点单 `ST1784010781572` 已软删除（`del_flag=2`）但明细有差异**
   → 扫描条件 `t.del_flag='0'` 正确排除，不会调账。

4. **金额不可按库位横向对比**
   → 移库不同步台账（`sumValuation` 只按物料分组，不受影响）。
   按物料/仓库汇总始终准确。

5. **三项取价按钮均为手动**
   → `priceInbound` / `carryOutbound` / `adjustStockTake` 无定时任务，
   台账会落后于实时库存。建议流程：入库计价 → 出库结转 → 盘点调账。
