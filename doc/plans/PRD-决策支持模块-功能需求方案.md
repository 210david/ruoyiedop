**一句话定位**：在不动各模块现有报表的前提下，新增一个统一的决策支持模块（`ruoyi-bi`），通过"统一指标层 + 驾驶舱 + 跨模块分析预警"三阶段建设，为管理层提供单一、可信、可下钻的经营决策视图。

---

## 1. 背景与问题陈述

系统已建成 12 个业务模块（销售 MK、投标 BID、采购 PMS、生产 MMS、质量 QMS、仓库 WMS、设备 DMS、安全生产 Safety、人力 HR、产品设计 PDM、财务 Fin、AI），各模块均已自带统计分析能力（合计约 70+ 个统计接口），但存在三个结构性问题：

1. **口径分散**：每个模块的统计 SQL 各自实现，同名指标口径不一（如"完工数"是否扣除质检不良），跨模块对比时数字打架；
2. **入口分散**：管理者要在 8 个看板之间来回切换，无法回答"采购延误到底影响了多少交付"这类跨模块问题；
3. **技术债**：平台首页聚合（`HomeController`）为取数直接 import 并注入 8 个模块的 domain/Mapper，耦合持续恶化。

**不解决的成本**：管理层看到的是互相矛盾的数字 → 不信任系统 → 回到 Excel 手工汇总 → 系统投入的价值感持续流失；同时 HomeController 模式一旦被新模块复制，模块裁剪与后续演进成本翻倍。

**模块成熟度说明**：财务模块（Fin）当前为边缘模块、功能尚不完善，本方案对财务类指标采取**弱化策略**（见第 7 节），不作为阶段一/二依赖。

## 2. 目标与成功指标

### 用户目标
- 管理层**一个页面**看清经营全貌，异常指标一眼可见，可一键下钻到原始单据；
- 任何核心指标在模块报表与决策模块中**数值一致**（同一口径）。

### 业务目标与衡量方式

| 目标 | 指标 | 基线 | 目标值 | 评估时点 |
|---|---|---|---|---|
| 管理层使用决策模块替代人工汇总 | 核心用户（厂长/总经理层）周活跃率 | 0 | ≥80% | 上线 1 个月 |
| 看全貌的效率 | 从打开系统到找到关键异常的路径数 | 8 个页面切换 | 1 个驾驶舱页 | 上线验收 |
| 口径可信 | 核心指标模块报表 vs 决策模块对账一致率 | 无 | 100% | 每日对账任务 |
| 技术债收敛 | HomeController 直连 Mapper 的模块数 | 8 | 0 | 阶段一验收 |
| 查询性能 | 驾驶舱首屏加载时长 | —（实时聚合） | ≤2 秒（读快照） | 上线验收 |

## 3. Non-Goals（本期明确不做）

| 不做 | 理由 |
|---|---|
| 不上数据仓库 / ETL 工具 / 第三方 BI 平台（FineBI 等） | 单库单体场景，指标字典 + 快照表足够；引入平台运维成本不匹配 |
| 不改造、不下线各模块现有报表 | 操作层日常仍依赖模块内报表，本模块只做管理层聚合视图 |
| 不做机器学习预测 | 数据量与业务成熟度不足；用同环比 + 移动平均外推即可；MK 已有销售预测（`/salesForecast`）**直接复用**，不重建 |
| 不做指标自助拖拽配置（自助 BI） | 使用者是管理层，非分析师；自定义看板放到 P2 观察 |
| 不做实时流式计算 | T+1 快照 + 当日实时兜底已满足决策频率 |
| 不建设财务深度分析（财务域主题看板、财务指标卡） | **Fin 为边缘模块且不完善**，待财务模块成熟后单独规划，本模块仅保留经 MK 数据可支撑的回款类指标 |

## 4. 用户角色与用户故事

| 角色 | 用户故事 | 优先级 |
|---|---|---|
| 总经理 | 作为总经理，我希望登录后在一个驾驶舱页看到销售/生产/质量/库存/采购的关键指标及同环比，以便 3 分钟内掌握经营全貌 | P0 |
| 总经理 | 作为总经理，当某指标超出阈值（如工单完成率 <85%）时，我希望该指标卡自动变红并给出归因提示，以便第一时间关注异常 | P1 |
| 生产厂长 | 作为生产厂长，我希望点击"工单完成率"下钻到具体延误工单列表并跳转生产模块处理，以便从"看到问题"到"处理问题"闭环 | P0 |
| 采购经理 | 作为采购经理，我希望看到"采购及时率 → 生产齐套率"的关联视图，以便判断延误发生在采购还是车间 | P1 |
| 销售总监 | 作为销售总监，我希望看到线索→商机→合同→回款的跨模块漏斗，以便定位转化断点 | P1 |
| 系统管理员 | 作为系统管理员，我希望按角色/部门控制驾驶舱数据可见范围（如车间主任只看本部门），以便满足数据权限要求 | P0 |
| 财务经理 | 作为财务经理，我希望决策模块的指标快照每日自动落库，以便查看任意历史时点的经营数据 | P0 |
| 部门经理 | 作为部门经理，我希望把月度经营分析导出为 Excel，以便线下汇报 | P1 |

**边界场景**：
- 空状态：某模块上线初期无数据，指标卡显示"—"而非 0，并提示数据来源模块（遵循规范 5.10 空状态）；
- 快照缺失：当日快照任务失败时，驾驶舱降级为实时查询并显示"数据非快照口径"角标；
- 无权限：用户访问无权限的主题看板时返回 403 页面，而非空图表。

## 6. 功能需求

### P0 — Must Have（没有即不成立）

#### F1 统一指标层（本模块的地基）

- **F1.1 指标字典**：新建 `bi_metric_dict` 表，字段含：指标编码、名称、所属域、口径定义（文字）、计算实现引用、维度（时间/组织）、刷新方式（快照/实时）、阈值（红/黄线，P1 启用）、责任人、**变更留痕**（`bi_metric_dict_log` 表记录口径变更人/时间/前后值）。
- **F1.2 模块统计接口规范（v1.1 修正架构）**：
  - 统一接口 `IModuleStatsProvider` **定义在 `ruoyi-common`**（方法：`getMetric(code, dims, range)` 返回统一 VO：指标编码、值、单位、部门维度、时间戳、数据标记）；
  - **各模块基于其现有 DashboardService / StatisticsService 扩展实现该接口**（复用既有取数逻辑，遵循规范 2.8：Dashboard Controller 独立、VO 放 `domain/vo/` 继承 `BaseEntity`），**不新建平行统计实现**；
  - `ruoyi-bi` 通过 Spring 注入 `List<IModuleStatsProvider>` 自动收集全部实现，**bi 模块 Maven 层不依赖任何业务模块**，避免依赖网（与规范 6.1 模块依赖方向兼容）。
- **F1.3 快照表与定时任务（v1.1 修正）**：
  - 新建 `bi_metric_snapshot` 表（指标编码、日期、**dept_id 维度**、维度值、数值），保留期 ≥24 个月；
  - Quartz 任务类 `BiMetricSnapshotTask` 放 `ruoyi-bi/task/` 目录，Bean 名 `biMetricSnapshotTask`，cron `0 0 1 * * ?`（遵循规范 2.9 定时任务规范）；
  - **幂等设计**：同日重跑先删后插（delete by metric_date），任务失败告警并支持手动重跑。
- **F1.4 HomeController 重构**：`/home` 取数从直连 8 模块 Mapper 改为调用各模块统计接口，消除跨模块 Mapper 依赖。**改动范围声明**：仅替换 Service 层取数实现，`/home` 接口契约（URL、返回结构）不变，`SysUserHomeLayout` 用户布局功能不受影响；重构后需回归首页全部卡片（含布局配置保存/恢复）。
- **F1.5 指标对账任务（v1.1 新增）**：每日快照完成后执行对账任务：抽取核心指标的实时值与快照值比对，不一致项写入 `bi_metric_check_log` 并告警；对账页面仅管理员可见。

验收标准：
- [ ] 指标字典中每条指标均有唯一编码与文字口径定义，同口径指标在系统中仅一处计算实现；
- [ ] 每日 01:00 快照任务成功执行，失败自动告警；同日手动重跑不产生重复数据（幂等验证通过）；
- [ ] HomeController 代码中不再 import 任何业务模块的 Mapper；首页回归用例全部通过；
- [ ] 对账任务连续运行 7 天，核心指标一致率 100%，不一致项均有 `bi_metric_check_log` 记录；
- [ ] `ruoyi-bi` 的 pom.xml 不含任何业务模块依赖（仅 ruoyi-common / ruoyi-framework）。

#### F2 决策驾驶舱（驾驶舱首页）

- 顶部核心指标卡 8~12 个（见第 7 节核心指标清单），每卡显示：当前值、同比/环比箭头、达标状态色（绿/黄/红）；
- **页面结构遵循规范 6.0 统计看板规范**：①顶部操作栏（时间范围 radio + 刷新按钮 + 自动刷新开关）②异常预警横幅区 ③KPI 指标卡（数字滚动动画 + 悬停上浮、左侧色条区分）④ECharts 图表区（resize 自适应、组件卸载 dispose）；
- 指标卡数据默认读 T-1 快照，切换"今日实时"时降级实时查询（带缓存，见 NFR）；
- 按登录人数据权限过滤（见 F5）；
- 支持用户级卡片排序与显隐（复用现有 `SysUserHomeLayout` 机制，**扩展而非重建**）。

验收标准：
- [ ] 首屏加载 ≤2 秒（快照模式）；
- [ ] 每个指标卡可点击进入对应主题看板或下钻列表；
- [ ] 无数据模块显示"—"与来源提示，不显示误导性的 0；
- [ ] 浏览器窗口缩放图表自适应、无控制台报错（图表 dispose 验证）。

#### F3 主题看板（5 个域，v1.1 修正：移除财务域）

生产域、质量域、销售域、库存域、采购域各一页，每页 = 本域核心指标卡 + 2~4 个分布/趋势图 + 异常列表。图表直接复用各模块看板已有的图表类型，数据源改走指标层。**设备/安全/人力/投标域指标并入驾驶舱指标卡，暂不设独立主题页**（避免页面过多摊薄维护精力，P1 视使用反馈增补）。

#### F4 指标下钻

- 任一指标 → 按维度（时间/组织）展开 → 定位到明细记录 → 跳转对应模块的标准列表页（带过滤参数）；
- 下钻路径在指标字典中登记（每指标最多 2 级下钻）；
- 跳转目标为**现有模块列表页**，通过 URL 参数触发既有高级查询（规范 4.3.2），不新建页面。

验收标准：
- [ ] 从驾驶舱任意指标卡 ≤3 次点击可到达原始单据列表；
- [ ] 跳转后模块页面按下钻条件自动过滤，原有列表功能不受影响。

#### F5 权限与数据权限（v1.1 修正：对齐规范 3.5 强制规范）

- 功能权限：沿用 RuoYi `@PreAuthorize`，菜单权限遵循规范 3.4 命名：`bi:dashboard:view`（驾驶舱）、`bi:board:{domain}:view`（主题看板）、`bi:metric:export`（导出按钮 F 权限）、`bi:metric:check`（对账页）；
- 数据权限（替代 v1.0 的"并集取交集"模糊表述）：
  - `bi_metric_snapshot` 按 3.5.1 分类为**统计/追溯类**：豁免归属字段填充，但**必须携带 `dept_id` 维度列**（各模块快照写入时按数据归属部门分粒度落库）；
  - 驾驶舱/看板查询按用户 `@DataScope` 等效语义过滤快照的 dept 维度（车间主任仅见本部门粒度数据；公司级汇总指标仅授权角色可见）；
  - 主题看板数据来自各模块统计接口时，沿用各模块已接入的 `@DataScope` 过滤（规范 3.5.3：经 Service 列表方法的统计随权限过滤，属预期行为）；
  - 快照/对账类表设计文档须注明"统计类豁免"，纳入 3.5.4 豁免清单维护。

验收标准：
- [ ] 车间主任登录仅见本部门粒度数据，公司级汇总指标对其隐藏或脱敏；
- [ ] 越权请求返回 403，前端不渲染空图表；
- [ ] 数据权限用例（本部门/本部门及以下/全部三类角色）测试通过。

### P1 — Should Have（上线后 1~2 个迭代内）

#### F6 跨模块指标关联分析

- 价值链路视图一：**线索 → 商机 → 合同 → 生产 → 交付 → 回款**（销售到现金，回款取 MK 回款数据，Fin 成熟后切换数据源），展示各环节转化率与停留时长；
- 价值链路视图二：**采购到货及时率 → 生产齐套率 → 订单交付率**（供应保障链），支持按月对比；
- 每个环节可下钻到 F4。

#### F7 阈值预警（v1.1 补充抑制规则）

- 在指标字典中配置阈值（红/黄线）与通知对象，Quartz 每日快照后执行规则匹配；
- 触发后在驾驶舱指标卡标红 + 站内通知（复用现有消息机制，遵循规范 5.14 消息通知设置）；
- **抑制规则**：同一指标同一预警级别 24 小时内不重复推送；级别升级（黄→红）立即推送；连续未恢复的预警每 3 天汇总提醒一次；
- 预警仅推送到订阅人，避免全员轰炸。

#### F8 报表导出

- 复用 HR 统计的 `reportType` 导出模式，驾驶舱/主题看板支持导出 Excel；
- 导出实现遵循规范 4.3.11 导出功能规范（强制）与 4.3.7 下载兼容规范；
- 导出记录写入操作日志。

#### F9 大屏模式

- 驾驶舱只读大屏版（轮播各主题看板），供车间/展厅部署；数据只读、自动刷新间隔可配（默认 5 分钟）。

### P2 — Future（本期不实现，架构预留）

- **自定义看板配置**：用户自选指标卡组合 → 架构上 F1 的指标编码化已为此预留；
- **财务域指标**（FIN_EXPENSE 月费用支出、FIN_CASH_FLOW 月现金流入）：**v1.1 降级至 P2**，待 Fin 模块完善后回补，届时 Fin 实现 `IModuleStatsProvider` 接口即可无改造接入；

## 8. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 驾驶舱首屏 ≤2s（快照）；实时模式单接口 ≤3s；快照任务每日 01:00 完成，全量 ≤10 分钟 |
| 缓存 | 推广 QMS 已验证的 Redis 缓存模式：实时查询统一 5 分钟缓存；缓存清空入口纳入管理功能 |
| 可用性 | 快照任务失败自动告警，可手动重跑（幂等）；驾驶舱降级策略见 F2 |
| 安全 | 遵循 RuoYi 权限体系与规范 3.5 数据权限；导出写操作日志；快照按 dept 维度过滤（见 F5） |
| 数据保留 | 快照保留 ≥24 个月；指标字典变更留痕（谁改的口径、何时生效，见 F1.1） |
| 兼容性 | 纯增量模块，不改各模块现有 Controller/Service 对外行为（HomeController 重构仅改实现不改接口契约） |

## 9. 分阶段实施计划

| 阶段 | 范围 | 交付物 | 建议周期 | 验收里程碑 |
|---|---|---|---|---|
| **一：口径治理 + 收敛** | F1（指标字典/接口规范/快照表/对账）+ F1.4 HomeController 重构；新模块接入遵循规范 1.2 新模块接入步骤 | 指标字典上线、22 个核心指标统一实现、首页解耦 | 2~3 周 | 对账一致率 100%；HomeController 零 Mapper 直连；首页回归通过 |
| **二：驾驶舱 + 看板** | F2、F3、F4、F5 + 新建 `ruoyi-bi` 模块 | 决策支持菜单上线：驾驶舱 + 5 域主题看板 + 下钻 + 权限 | 3~4 周 | 首屏 ≤2s；核心用户周活跃试点验收 |
| **三：分析 + 预警** | F6、F7、F8、F9 | 价值链路视图、阈值预警、导出、大屏 | 2~3 周 | 至少 2 条跨模块链路可用；预警触达与抑制规则验证 |

**关键顺序原则**：阶段一先行且不可跳过——口径不统一时看板做得越快，输出错误结论越快。阶段二可与阶段一的部分接口实现并行（UI 先用 mock 指标）。

## 10. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 口径确认反复（业务方对"什么算完工"各执一词） | 阶段一延期 | 评审会逐条签字确认；争议指标先标注口径 v0 上线，字典留痕后续迭代 |

| 数据权限过滤遗漏导致越权可见 | 数据安全 | 快照 dept 维度过滤 + DataScope 用例三类角色测试前置，阶段二验收必测项 |
| ruoyi-common 接口膨胀 | 公共模块治理 | 仅放 `IModuleStatsProvider` 单一接口；后续若扩展可抽 `ruoyi-bi-api` 独立模块 |
